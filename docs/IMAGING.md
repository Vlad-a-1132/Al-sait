# Закрытый архив исследований

## Локальная проверка

Откройте `http://127.0.0.1:3136/imaging` (порт зависит от запущенного Next.js).
Тестовая учётная запись: **root / root**. Это пользователь приложения, а не ОС.
Используйте только синтетические файлы без данных пациентов.

```powershell
$env:IMAGING_TEST_MODE='1'
npm run dev -- --port 3136 --hostname 127.0.0.1
```

Вход проверяется сервером. Сессия — случайный секрет в HttpOnly / SameSite=Strict cookie,
действует 8 часов. При HTTPS cookie получает Secure. Пароли хранятся как scrypt-хеши.
Внешний HTTP запрещён. Тестовый режим по умолчанию доступен только с localhost;
production без настроенных начальных учётных данных закрывается с 503.

На странице можно загружать несколько файлов, перетаскивать их, искать, просматривать,
скачивать, создавать сотрудников и токены передатчиков. Пауза/закрытие вкладки не делает
незавершённый файл доступным. Повторно выберите исходный файл: сначала вычислится SHA-256,
затем передача продолжится с сохранённого смещения. Поиск: имя файла, без регистрации в аналитике.

PNG, JPEG, GIF, WebP и PDF определяются по сигнатуре файла. SVG, HTML и все другие форматы
отдаются только как вложения. DICOM-просмотр не реализован. Исходные изображения не проходят
через публичный оптимизатор Next Image. Страница исключена из robots и аналитики сайта.
PDF отрисовывается постранично локальной библиотекой PDF.js, с переключением страниц и
масштабом. Worker, шрифты и декодеры отдаются своим защищённым API; внешних просмотрщиков нет.

## Хранилище и надёжность

По умолчанию: `../altamed-imaging-private` относительно рабочего каталога Node.js.
Это **вне проекта**, `public`, Git и результатов сборки. Можно задать абсолютный
`IMAGING_DATA_DIR`. Внутри проекта и через ссылку внутрь проекта хранилище не принимается.
Каталоги имеют права 0700, новые файлы 0600 на Linux. Права ОС и резервные копии
настраивает администратор при размещении. Каталог должен быть постоянным при обновлениях сайта.

Метаданные — отдельные небольшие JSON-файлы с атомарной заменой и fsync. Загрузка пишется
потоком в `partials/<uuid>.part`. После проверки длины и SHA-256 файл перемещается в
`blobs/<sha256>.bin`, а запись публикуется в каталоге `files/`. Имена пользователей не
используются как пути. Содержимое больших файлов не читается целиком в память.

Это файловый каталог метаданных для одного VPS / локального файлового тома, без внешней СУБД.
Блокировки работают между процессами одного хоста, в том числе при перезапуске Next.
Не размещайте этот каталог на NFS и не запускайте несколько серверов с независимыми копиями:
для такого масштабирования нужна общая транзакционная БД и объектное хранилище.

Часть считается принятой только после записи, fsync и фиксации нового смещения. Если запрос
оборвался, часть откатывается; после падения процесса лишний хвост отбрасывается при следующей
записи. Завершение идемпотентно. Один SHA-256 создаёт одну архивную запись, даже при двух
одновременных загрузках. При несовпадении хеша — 422, файл в архив не попадает.

Лимит одного файла: **419430400 байт (400 МиБ)**. Максимальная часть: **4194304 байта**.
Квота по умолчанию — 10 ГиБ, с резервированием полного размера незавершённых файлов.
Дополнительно оставляется 512 МиБ свободного диска. Не более 10 активных загрузок на
передатчик/сотрудника и 100 на весь архив. Срок незавершённой загрузки — 48 часов после
последней принятой части. Очистка запускается при создании новой загрузки, через CLI
`cleanup` или администраторский API. Квота архива не включает журнал, ОС и старые метаданные.

`audit.jsonl` содержит входы, отказы, начало/завершение/ошибки загрузок, скачивания,
изменения доступа. Имена файлов, поисковые запросы, пароли и токены в журнал не пишутся.
Журнал ротируется после 10 МиБ, хранится до пяти предыдущих файлов. Для постоянной очистки
незавершённых загрузок администратор может запускать CLI `cleanup` по расписанию.
Создание загрузок ограничено 120 запросами в минуту на передатчик/сотрудника; архив —
не более 10000 файлов. Повторные запросы к уже загруженному содержимому тоже учитываются.

## Сотрудники и передатчики

Войдите как администратор → **Сотрудники и передатчики**.

* Сотрудник: загрузка, список, просмотр и скачивание всего архива.
* Администратор: те же права плюс создание/отключение сотрудников и токенов.
* Токен передатчика: только создание, запись, проверка состояния, завершение и отмена
  **собственных** загрузок. Список, просмотр и скачивание архива запрещены.

Пароль нового сотрудника — минимум 10 символов. Отключение или сброс пароля отзывает
сессии; повторное включение не восстанавливает старую сессию. Себя и последнего активного
администратора отключить нельзя. Токены показываются один раз, на диске хранится только хеш.

CLI запускается из корня проекта с теми же переменными окружения, что у приложения:

```powershell
node scripts/imaging-admin.cjs users
$env:IMAGING_NEW_PASSWORD='ЗдесьНовыйДлинныйПароль'
node scripts/imaging-admin.cjs add-user doctor1 staff
node scripts/imaging-admin.cjs reset-password root
Remove-Item Env:IMAGING_NEW_PASSWORD
node scripts/imaging-admin.cjs disable-user doctor1
node scripts/imaging-admin.cjs enable-user doctor1
node scripts/imaging-admin.cjs create-token 'Компьютер КТ'
node scripts/imaging-admin.cjs revoke-token UUID_ТОКЕНА
node scripts/imaging-admin.cjs cleanup
```

Пароль не передавайте аргументом командной строки. В production начальные
`IMAGING_BOOTSTRAP_USER` / `IMAGING_BOOTSTRAP_PASSWORD` применяются только к новому хранилищу;
для существующего используйте reset-password. Учётку root/root необходимо изменить до
перехода к реальным данным. Тестовый режим должен быть отключён.

## API передатчика v1

Базовый адрес локально: `http://127.0.0.1:3136/api/imaging`.
При размещении: `https://ВАШ-ДОМЕН/api/imaging`.

Это API проекта с подтверждаемыми смещениями, **не заявление о совместимости с tus**.
Все запросы передатчика содержат `Authorization: Bearer img_…`. Токен никогда не помещается
в URL. CORS не включён. POST/GET передатчика не требуют cookie и CSRF-заголовка.
Браузерные изменения с cookie требуют совпадающий Origin и `X-Imaging-Request: 1`.

### 1. Начать или продолжить

`POST /uploads`, `Content-Type: application/json`:

```json
{"name":"test-study.bin","size":419430400,"sha256":"64 шестнадцатеричных символа в нижнем регистре"}
```

SHA-256 вычисляйте по **полному** файлу потоково. Отправляйте только завершённые файлы:
программа, которая создала исследование, не должна продолжать запись во время передачи.
Для папок исследования клиент в будущем должен сохранять состав серии; пока каждый файл
хранится самостоятельно. Следящая за папкой программа пока не входит в этот модуль.

Ответ `201` для новой или своей ранее начатой загрузки:

```json
{"id":"UUID","status":"pending","offset":0,"size":419430400,"expiresAt":"2026-10-24T10:00:00.000Z"}
```

Если содержимое уже в архиве, также `201`:

```json
{"status":"complete","fileId":"SHA256","duplicate":true,"offset":419430400,"size":419430400}
```

Повторный POST с тем же SHA-256 и тем же токеном находит свою незавершённую загрузку.
При уже загруженном файле не нужно повторять передачу. При другом имени остаётся первое
имя архивной записи. Не используйте имя файла как критерий дубля.

### 2. Узнать подтверждённое смещение

`GET /uploads/UUID` → `200` с состоянием, `offset`, `size`, `expiresAt`.
`HEAD /uploads/UUID` → `200`, заголовки `Upload-Offset` и `Upload-Length`, без тела.
Другому передатчику эта загрузка недоступна (`404`). Смещение учитывает только целиком
зафиксированные части. После обрыва/таймаута сначала запросите смещение.

### 3. Отправить часть

`PATCH /uploads/UUID`:

```http
Authorization: Bearer img_…
Content-Type: application/offset+octet-stream
Upload-Offset: 0
Content-Length: 4194304

[сырые байты части]
```

До 4194304 байт в одном запросе, последняя часть может быть короче. Ответ `204` без тела,
заголовок `Upload-Offset` — новое подтверждённое смещение. При `409` запросите состояние и
повторите с правильного смещения. Оборванная часть повторяется, уже принятые части не теряются.
Параллельные части одной загрузки не поддерживаются; разные файлы могут передаваться отдельно.

### 4. Зафиксировать

`POST /uploads/UUID/complete`, без тела → `200`:

```json
{"id":"UUID","status":"complete","offset":419430400,"size":419430400,"fileId":"SHA256","duplicate":false,"expiresAt":"…"}
```

Сервер повторно вычисляет SHA-256 потоково. До этого вызова файл скрыт из списка.
Повтор после потери ответа безопасен. `duplicate:true` означает, что другая загрузка уже
поместила это содержимое в архив. `DELETE /uploads/UUID` отменяет незавершённую загрузку,
удаляет временные данные и возвращает `200 {"ok":true}`.

### Ошибки

Всегда JSON `{"error":{"code":"…","message":"…"}}` (для HEAD тело отсутствует).

| HTTP | Значение |
| --- | --- |
| 400 | Некорректный JSON, имя, SHA-256 или заголовки |
| 401 | Нет входа / токен неверен или отозван |
| 403 | Прав недостаточно, другой Origin или запрещён внешний HTTP |
| 404 | Неизвестный маршрут / чужая загрузка / отсутствующий файл |
| 409 | Неверное смещение, загрузка не завершена или уже закрыта |
| 410 | Истёк срок загрузки; создайте заново |
| 413 | Превышен размер файла, части или JSON |
| 415 | Неправильный Content-Type |
| 416 | Неверный Range при скачивании |
| 422 | Контрольная сумма не совпала; отмените и начните заново |
| 423 | Загрузка занята другим запросом; повторите с задержкой |
| 429 | Лимит входов или активных загрузок |
| 503 | Не настроено / недоступно хранилище или HTTPS |
| 507 | Квота или свободное место закончились |

Повторять автоматически можно сетевые ошибки и 409/423/503 с проверкой состояния и
увеличивающейся задержкой. Для 429 учитывайте Retry-After, если он присутствует.
Число повторов ограничивайте; постоянные ошибки показывайте оператору передатчика.

### Готовый пример отправки

```powershell
$env:IMAGING_UPLOAD_TOKEN='img_ТОКЕН_ИЗ_ИНТЕРФЕЙСА'
node scripts/imaging-send.cjs http://127.0.0.1:3136 'C:\Test\test-study.bin'
Remove-Item Env:IMAGING_UPLOAD_TOKEN
```

CLI считает SHA-256 потоком, передаёт части и продолжает с подтверждённого смещения.
Для внешнего адреса он требует HTTPS. При повторном запуске после обрыва продолжает ту же
загрузку. Это эталон API для будущего передатчика, без наблюдения за папкой.

## Размещение — после отдельного решения

Обновление исходников в GitHub само по себе не подтверждает размещение архива на хостинге.
Настройки ниже — инструкция для администратора, а не подтверждение работы production.

Для VPS: поддерживаемая Node.js версии не ниже 22.13 (требование пакета PDF.js), Next в режиме сервера, постоянный приватный
каталог, свободный диск, TLS на Nginx. Проверить актуальность серверных зависимостей до
работы с реальными медицинскими данными. Существующий вход /admin не используется архивом.

Переменные окружения:

```text
IMAGING_TEST_MODE=0
IMAGING_DATA_DIR=/var/lib/altamed-imaging
IMAGING_ORIGIN=https://ВАШ-ДОМЕН
IMAGING_TRUST_PROXY=1
IMAGING_BOOTSTRAP_USER=root
IMAGING_BOOTSTRAP_PASSWORD=НОВЫЙ_ДЛИННЫЙ_ПАРОЛЬ
IMAGING_QUOTA_BYTES=10737418240
```

Внешний тестовый доступ с root/root требует отдельного явного
`IMAGING_TEST_MODE=1` + `IMAGING_ENABLE_REMOTE_TEST=1`; он не включается автоматически.
Для реальных файлов эту настройку не применять. Приложение Node.js привязать к loopback,
чтобы доверенные proxy-заголовки мог задавать только Nginx.

В HTTPS server-блок Nginx добавить отдельный location для API (пример; сайт остальной не менять):

```nginx
location ^~ /api/imaging/ {
    client_max_body_size 5m;
    client_body_timeout 120s;
    proxy_request_buffering off;
    proxy_buffering off;
    proxy_read_timeout 180s;
    proxy_send_timeout 180s;
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

400 МиБ передаются частями по 4 МиБ, поэтому поднимать лимит каждого HTTP-запроса до 400 МиБ
не требуется. Не добавляйте `alias`/`root` на приватный каталог. Не кешируйте `/imaging` и
`/api/imaging`, включая CDN. Копируйте весь каталог хранилища согласованным snapshot,
с проверкой восстановления и ограниченными правами доступа.

## Проверки

```text
node --test tests/imaging.test.cjs
node tests/imaging-http-smoke.cjs
```

Второй тест запускает собственный локальный Next на 3137, убивает только его процесс
во время записи части, перезапускает и докачивает 400 МиБ. Проверяет авторизацию,
дубли, точную длину и SHA-256 скачанного файла. Отчёт: `tmp/imaging-check-20261022/report.json`.
Это локальный HTTP-тест. Production HTTPS и настройки хостинга им не проверяются.
Тестовый файл остаётся в локальном архиве для ручной проверки.

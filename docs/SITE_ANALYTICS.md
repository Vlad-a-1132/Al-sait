# Статистика сайта Альтамед-С

Панель: `https://altamed-c.ru/prices/analytics`. В разделе `/prices` добавлена ссылка «Статистика сайта». Доступ к странице, JSON и CSV защищён на сервере существующими `PRICES_TEST_USER` и `PRICES_TEST_PASS`. Используется тот же логин и пароль, что у `/prices`. Без обеих переменных доступ закрыт. Пароли не попадают в клиентский JavaScript. Страница исключена из индексации и публичной навигации сайта.

## Подключение и хранение

Установка новых пакетов и миграция базы не нужны. После обычной сборки и перезапуска Next.js сборщик автоматически работает на публичных страницах. До подключения собственной аналитики история не собиралась и автоматически восстановлена не будет. Сведения о браузерах и новых этапах форм доступны только с момента этого обновления; старые события не переписываются. Для обеих систем нужен JavaScript.

По умолчанию события записываются в `data/analytics/YYYY-MM-DD.jsonl`. Папка закрыта от HTTP-доступа, исключена из Git и должна быть доступна процессу Node.js для записи. Запись выполняется добавлением строк, без перезаписи предыдущих событий. Журнал хранится 180 дней; старые файлы удаляются при поступлении новых событий. Обновление страницы отчёта не изменяет журнал. Повторно доставленные события с одним ID учитываются один раз.

Для сохранения статистики при замене каталога приложения можно задать на сервере отдельную постоянную папку:

```env
ANALYTICS_DATA_DIR=/var/lib/altamed/analytics
```

Создайте её с правом записи для пользователя, от которого запускается Next.js. Не размещайте её в `public`. При Docker-развёртывании подключите постоянный том. Решение рассчитано на текущий сервер Node.js/PM2 с постоянным диском. Для нескольких серверов нужен общий журнал или перенос хранения в базу. Эфемерная файловая система serverless-хостинга не подходит.

## Подсчёт

- Посетитель: анонимный ID браузера в localStorage, срок 365 дней. Разные браузеры и устройства считаются отдельно. Если localStorage недоступен, используется память вкладки, и точность между перезагрузками снижается.
- Визит: общий для вкладок браузера ID; новый после 30 минут без событий. В выбранном периоде считаются визиты, в которых были события. Один визит на границе суток может попасть в два суточных значения, но в общем итоге учитывается один раз.
- Просмотры: первое открытие и переходы по сайту, включая навигацию Next.js. Изменения параметров адреса считаются новыми просмотрами, но их значения в журнал не записываются.
- Источник: UTM source/medium/campaign, рекламные метки yclid/gclid (только факт наличия), поисковик, внешний домен либо прямой заход. Источник закреплён за визитом. Полный внешний URL и поисковый запрос не сохраняются.
- Браузеры: Chrome, Safari, Яндекс Браузер, Firefox, Edge, Opera, Samsung и прочие. Сохраняются только семейство, основная версия, ОС и тип устройства. Полный User-Agent и отпечаток браузера не сохраняются. iPad в режиме настольного Safari распознаётся как планшет. Старые данные группируются как неизвестные.
- Клики: ссылки и кнопки с названиями, страницами, размещением и ID. Отдельно различаются шапка, мобильная панель, подвал, формы и секции страницы. Важные кнопки имеют явные ID; остальные получают ID по месту в своём блоке, который может измениться при перестройке вёрстки. Дополнительно учитываются пять существующих действий калькулятора анализов.
- Воронка форм: показ не менее 10% формы на экране, первое нажатие внутри, первое изменение поля, действительный запрос отправки, подтверждённое сохранение. Для каждого наблюдаемого этапа учитываются уникальные визиты. Промежуточные этапы не восстанавливаются по поздним событиям, порядок событий не проверяется. Конверсия формы — доля увидевших её визитов, в которых также есть сохранение в том же периоде и группе. При отсутствии показов отображается прочерк. Есть разбивка по форме, странице и размещению.
- Ошибки: обязательное поле, формат, отсутствие согласия, клиентская проверка, сеть и сервер. Передаются только код, тип поля, браузер, размещение и при наличии HTTP-статус. Значения полей и сырые тексты ошибок не передаются.
- Отправки форм: действительные запросы форм записи на странице, страницы `/appointments`, обратного звонка, контактов и заявки из чата. Ошибки заполнения до отправки запроса не увеличивают показатель.
- Сохранённые заявки: только подтверждённое сохранение через `/api/appointment`. Сбой SMTP не отменяет уже сохранённую заявку. Клиентский сборщик не может прислать событие успешной заявки в публичный endpoint.
- Конверсия в заявку: визиты с сохранённой сервером заявкой / все визиты × 100%. Повторные заявки в одном визите не увеличивают эту долю повторно.
- Интерес к обращению: отдельная доля визитов с нажатием на телефон, переходом в мессенджер либо к онлайн-записи. Учитываются `online.altamed-c.ru`, `/appointments` и ссылки на блок формы. Клик не подтверждает звонок или состоявшуюся внешнюю запись. Подтверждённые записи внешнего сервиса потребуют его интеграции; она не подключена.

Известные боты, служебные `/prices`, `/admin`, `/call-center`, `/api`, `/_next` исключены. Содержимое полей форм, имена, телефоны, email, IP-адреса, параметры поиска и запись экрана не сохраняются в журнал аналитики. Поля событий проверяются на сервере; размер пакета и частота ограничены. IP используется только для кратковременного ограничения частоты в памяти процесса. Статистика описывает браузерные события, а не доказанные уникальные личности; блокировщики и отключённый JavaScript могут снижать показатели.

## Отчёты

Периоды: сегодня, вчера, 7, 30, 90 дней или произвольный диапазон до 93 дней. Часовой пояс — Москва. Фильтры по семейству браузера и устройству применяются ко всем показателям, таблицам, воронке и CSV. Таблицы источников, страниц, страниц входа, браузеров, кликов, ошибок, кампаний и устройств показывают до 100 строк. Итоги используют все события периода. CSV содержит сводку, дни, таблицы, формы и цели; файл также защищён паролем. Значения CSV защищены от выполнения формул при открытии в таблицах. Поля API `conversionRate`/`convertedVisits` сохранены для совместимости и относятся ко всем целям; основной показатель панели — `leadConversionRate`.

Если не удаётся читать хранилище, панель показывает ошибку, а не пустой успешный отчёт. Сбой записи аналитики не препятствует сохранению заявки. Для резервного копирования достаточно сохранять папку `ANALYTICS_DATA_DIR`.

## Доставка событий

В браузере хранится ограниченная очередь: до 200 событий, не дольше 24 часов. У каждого события свой ключ localStorage, поэтому вкладки не перезаписывают очередь друг друга. Обычная отправка через fetch удаляет события только после подтверждения сервером. Сеть, таймауты и ответы 408/429/5xx приводят к повторным попыткам с интервалом 2–60 секунд. Невалидные запросы с прочими 4xx отбрасываются. При закрытии страницы используется beacon; его результат не считается подтверждением сервера, поэтому оставшиеся ID могут доставиться повторно при следующем открытии. Отчёты исключают дубли по ID. Время события сохраняется при доставке в пределах суток.

Если localStorage запрещён, очередь работает в памяти и не переживает закрытие страницы. Если посетитель не вернулся, а beacon не доставился, гарантировать восстановление события нельзя. Технические события не влияют на результат отправки самой заявки. Новые заявки получают UUID, чтобы одновременно сохранённые заявки не совпадали по ID.

## Яндекс Метрика

Счётчик: `105270439`. Код загружается только на публичных страницах `altamed-c.ru` и `www.altamed-c.ru`; локальные копии и служебные разделы не инициализируют его. Используется `defer: true`: первый и последующие просмотры отправляются одним обработчиком, одинаковый первый вызов при повторном монтировании React не дублируется. Очередь `ym` создаётся до загрузки внешней библиотеки, поэтому ранние вызовы не отбрасываются. Вебвизор отключён. Автоматические карта кликов и отслеживание внешних ссылок заменены явными событиями для нужных действий.

Передаются пути без поисковых запросов и произвольных URL-параметров; допускаются UTM source/medium/campaign и рекламные yclid/gclid для атрибуции Яндекса. Рекламные ID не записываются в наш журнал. Дополнительные параметры целей: `page`, `form`, `placement`, `button_id`, `error_code`, `field`.

Сохранение заявки записывается в собственную аналитику на сервере. В Яндекс цель отправляется после ответа API с ID сохранённой заявки, один раз для этого ID на странице. Если посетитель закрыл страницу до ответа, библиотека Яндекса заблокирована или его запросы не доставлены, цель может отсутствовать в Метрике при наличии записи у нас. Передача офлайн-конверсий через API Яндекса не подключена.

### Однократная настройка целей в счётчике

Создание целей в аккаунте Яндекса требует доступа владельца и не выполняется коммитом на GitHub. В настройках счётчика проверьте существующие цели и создайте недостающие как «Целевое событие» с **точным совпадением** идентификатора. Уже настроенные идентификаторы не нужно дублировать.

| Идентификатор | Значение | Назначение |
| --- | --- | --- |
| `appointment_sent` | Сохранена заявка из встроенной формы или `/appointments` | Основная конверсия |
| `callback_sent` | Сохранена заявка на обратный звонок | Основная конверсия |
| `contact_sent` | Сохранено обращение из контактов | Основная конверсия |
| `chat_sent` | Сохранена заявка из чата | Основная конверсия |
| `phone_click` | Нажатие на телефон | Интерес к обращению |
| `messenger_click` | Переход в мессенджер | Интерес к обращению |
| `booking_click` | Переход к онлайн-записи или форме | Интерес к обращению |
| `form_view` | Форма видна посетителю | Этап формы |
| `form_click` | Первое нажатие внутри формы | Этап формы |
| `form_start` | Первое изменение поля | Этап формы |
| `form_submit` | Запрос отправки формы | Этап формы |
| `form_error` | Проверка поля, сеть или сервер помешали отправке | Диагностика |
| `lab_add`, `lab_remove`, `lab_call`, `lab_booking`, `lab_copy_list` | Существующие действия раздела анализов | Дополнительные действия |

Не используйте простую автоцель отправки формы как подтверждение сохранённой заявки: она может учитывать попытку, не прошедшую проверку. Перед сравнением систем согласуйте период, часовой пояс и выбранную цель. Совпадение счётчиков один в один не гарантируется из-за блокировщиков, фильтров, атрибуции и разных условий доставки.

Официальные инструкции: [инициализация](https://yandex.ru/support/metrica/ru/code/counter-initialize), [целевые события](https://yandex.ru/support/metrica/ru/general/goal-js-event), [особенности целей отправки формы](https://yandex.ru/support/metrica/ru/simple-goal/form).

# Обновление рабочего сайта

После установки команды на VPS войдите по SSH и выполните:

```bash
update-altamed
```

Также сохранён привычный вариант:

```bash
/var/www/update-altamed.sh
```

Команда получает последний коммит `master`. GitHub Actions заранее собирает его на Linux с Node 22 и публикует готовый архив. Если сборка ещё идёт, команда ожидает её до 20 минут. Сборка на VPS не запускается.

Перед установкой проверяются контрольная сумма, соответствие коммиту и файлу зависимостей. Новая версия запускается на отдельном порту, доступном только с самого сервера. Проверяются главная, «О нас», контакты, вход, архив и API. Рабочий сайт в это время продолжает отвечать.

При переключении сохраняются прежняя сборка, зависимости, идентификатор коммита, окружение и конфигурация PM2. `.env.local`, записи пациентов и закрытое хранилище не заменяются. Перезапускается только процесс `altamed-sait`. Если проверка после переключения не проходит, предыдущая версия возвращается автоматически.

Полезные команды:

```bash
update-altamed --check
update-altamed --rollback
```

Резервные копии находятся в `/root/altamed-deploy-backups/`, служебные файлы обновления — в `/var/www/altamed-updates/`. Резервные копии автоматически не удаляются; следите за свободным местом.

В GitHub сборки видны во вкладке Actions → Prepare site update. Внешние настройки и медицинские файлы в сборку не включаются. Версия Node рабочего процесса при таком обновлении сохраняется.
